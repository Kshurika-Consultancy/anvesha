## Covered behavior

- Committed jobs survive API restart and are visible to an independent worker/store.
- Client-scoped idempotency, input validation, hidden internal fields, and owner isolation across every job route.
- Transactional claims, attempt exhaustion, expired-lease recovery, stale publication rejection, cancellation and deletion during retrieval.
- Injected database failure rolls back both result publication and terminal state change.
- Immutable result snapshots, stable pagination, empty success versus partial source failure, and sanitized errors.
- Feedback snapshot/result membership, replacement instead of repeated votes, default-off learning consent, and delete cascade.
- Safe FTS syntax, rights metadata, deterministic RRF, source-specific provenance, and IDNA destination preservation.
- Optional provider requests use a fixed host, validated entity IDs, no redirects, bounded payloads, and mocked network failures.
- Tracking checker rejects unknown/cyclic tasks, missing completion evidence, broken links, untracked code reminders, and missing source rights.

## Review findings resolved

1. Whitespace-only idempotency header produced 500; now returns 422.
2. Invalid imported URLs could later fail ranking; ingestion now shares ranking URL validation.
3. Legacy IDNA could turn faß.de into fass.de; nontransitional UTS46 now preserves the correct destination and deduplicates its A-label correctly.
