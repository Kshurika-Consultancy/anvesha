# Security and privacy boundaries

This initial MVP is for a single-host local deployment. Keep the API bound to loopback. Public hosting needs ANV-008 quotas, backup/restore retention, abuse controls, operational review, and transport/security configuration. The demo is not a production security certification.

- Every search endpoint requires `X-API-Key`. Use a randomly generated key of at least 24 ASCII characters; initialize generates a 32-byte random secret. Raw keys are not stored in job records. Each configured key defines a distinct owner; replacing a key does not migrate its old jobs.
- All clients of an instance share the operator-imported document corpus. Import only data intended for those clients. Job history and feedback are owner-scoped; document-level tenant isolation is not implemented.
- The database contains query text, snapshots, and feedback. Restrict filesystem access and backups. It is not encrypted by the application. API access logs may contain job IDs but must never log headers or request bodies.
- Learning opt-in defaults off; no training is performed. ANV-026 adds persisted search expiry and bounded worker cleanup; new setups default to seven days, old saved configurations/jobs keep their previous lifetime. Search deletion cascades associated records in the active database but is not a forensic erasure guarantee for backups, WAL or disk pages. See [retention controls](docs/PRIVATE_RESEARCH.md#search-history-retention). Backup deletion remains ANV-008.
- Only the fixed Wikidata endpoint is used for optional live retrieval; no arbitrary URL is fetched. Enabling it sends the submitted query to Wikimedia. Provide a real operator User-Agent/contact and review the source manifest.
- Rank scores are not truth probabilities. Wikidata results are metadata-only; the source webpages are not verified. Imported text is data, not executable instructions.
- SQLite files must be on local disk. Avoid network filesystems. Worker leases prevent stale publication but do not promise exactly-once external calls.
- ANV-022 makes LLM ranking the default for new searches, currently only for the local corpus. It requires operator configuration and transmits the original query and bounded candidate text to that endpoint. Select `ranking: "lexical"` explicitly for no model processing. A loopback gateway can forward externally; Anvesha cannot verify its egress, retention or training behavior. Review processing rights and provider policies, especially when upgrading a configured external endpoint. No model or gateway is automatically installed; no tools or client keys are sent to a model.
- Model responses must contain a validated permutation of supplied IDs or bounded ordinal grades under the selected contract; prompt injection can still harm ordering. Output validation prevents adding result URLs or changing source content, not every relevance error. Strict deadlines, cancellation/lease/expiry checks and lexical fallback bound this optional stage. Upgrade every API/worker process before accepting jobs against an upgraded database. Expiry cannot recall in-flight model processing or external logs.
- CLI API commands disable access logs. Gateways and proxies have their own logs. The bundled browser loads same-origin assets only, uses restrictive CSP and no-referrer/no-store headers, renders content as plain text, and keeps its key in tab memory. Reload/Disconnect does not delete server records. CDN-backed interactive docs are disabled; OpenAPI remains public. Source links and browser extensions are separate trust boundaries. There is no blanket anonymity or untracked-search guarantee.
- `setup` creates a plaintext private configuration containing the client key and any model key, requests POSIX mode 0600 and refuses overwrite. Restrict inherited Windows ACLs and backups. Compose uses a non-root core image and loopback host port; the optional model runtime has separate permissions/licences. Do not include `.anvesha`, keys or real corpus files in image build contexts. Review [setup and upgrade guidance](docs/PRIVATE_RESEARCH.md).

The maintainer has not yet established a verified private vulnerability-reporting route. Report issues privately through an established company channel; do not publish secrets or exploit details in public issues. Establish a verified disclosure route before M6 public release (ANV-014).
